# 3 分钟项目演示脚本

> 面试时如果有机会展示项目，3 分钟足够让老师看到：你真的做过、能讲清、能复盘。
> 不要念代码；边操作边讲“为什么”。

## 结构

### 0:00–0:20 我是谁、做了什么

> 我做了一个最小嵌入式系统：一个按钮控制 LED，串口输出状态。它覆盖了 GPIO 输入输出、上拉、去抖和状态保持。

### 0:20–1:10 演示

- 上电，LED 灭，串口打印 ready。
- 按一下，LED 亮，串口 `LED ON`。
- 再按一下，LED 灭。
- 快速连按，说明去抖后每次只翻转一次。

边操作边说：

> 按钮接 GPIO4，用内部上拉，所以没按下是高电平、按下是低电平；LED 通过 330Ω 电阻接 GPIO13，限制电流。

### 1:10–1:50 怎么实现

> 程序每轮读按钮，记录最后一次变化时间；如果 20ms 内没有新变化，认为状态稳定；稳定状态从高变低时翻转 LED。这样避免机械抖动导致一次按下多次触发。

### 1:50–2:20 失败与修正

> 第一次 LED 不亮，我以为是代码问题，后来用万用表发现 LED 极性接反；还有一次按钮读数乱跳，是因为输入悬空，加上拉后稳定。从那以后我先测通断和电压，再怀疑代码。

### 2:20–2:50 学到什么 / 下一步

> 我学到了输入要有确定电平、机械按键要去抖、状态变化要可观察。下一步我想用 PWM 做呼吸灯，再加一个传感器，把系统扩展到“感知→判断→执行”。

### 2:50–3:00 收尾

> 这个项目很小，但它是完整的输入→判断→输出闭环；我也能说清每一处为什么这样接。

## 拍摄/演示要点

- 光线充足，镜头能看到面包板、芯片和串口窗口。
- 先演示，再解释；不要一上来念代码。
- 串口窗口放大，让老师看到状态变化。
- 说“我遇到的问题是……我后来……”比“一切顺利”可信。
- 不要声称没做过的功能；不会的就说不确定。

## 没有硬件怎么办

- 用 Wokwi 或 Tinkercad 搭同样电路，录屏演示。
- 说明“这是仿真，验证了逻辑；真实硬件我下一步会做”。
- 仿真不能替代电源/地/噪声/发热的真实问题，要诚实说明边界。
