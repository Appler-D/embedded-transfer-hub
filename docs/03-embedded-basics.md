# 嵌入式基础：从 GPIO 到 RTOS

> 嵌入式不是“写单片机代码”这么窄。它是在资源、功耗、实时性和可靠性约束下，让一个物理系统稳定工作。

## 1. 什么是嵌入式系统

嵌入式系统是“藏在产品里的专用计算机”：它采集传感器、做判断、控制执行器，并和外界通信。

例子：

- 洗衣机：水位/重量传感器 → MCU → 电机/进水阀。
- 汽车 ECU：曲轴/氧传感器 → MCU → 喷油/点火。
- 无人机：IMU/气压计 → 飞控 → 电机。
- 手机：里面不止一个 MCU，还有 SoC、基带、电源管理、传感器 hub。
- 智能家居：ESP32 → Wi-Fi → 继电器/灯。

特点：专用、成本敏感、功耗敏感、常常要求实时、要长期稳定运行。

## 2. MCU、SBC、PC 的区别

| | MCU | SBC（树莓派等） | PC |
| --- | --- | --- | --- |
| 操作系统 | 裸机/RTOS | Linux | Windows/Linux |
| 内存 | KB–MB | GB | GB |
| 实时性 | 强 | 一般 | 弱 |
| 功耗 | mW–W | W | 几十–几百 W |
| 启动 | 毫秒级 | 秒级 | 十秒级 |
| 典型任务 | 电机、传感器、控制 | 视觉、网络、AI | 开发、训练 |
| 例子 | STM32、ESP32、AVR | 树莓派、Jetson | 笔记本 |

P0 的分工：MCU 管实时运动和限位，SBC/PC 管感知与模型。

## 3. 单片机里面有什么

```text
CPU + Flash（存程序）+ SRAM（存数据）
+ GPIO + 定时器 + ADC + 通信外设（UART/I2C/SPI）
+ 中断控制器 + 看门狗 + DMA
```

- **Flash**：掉电不丢，放程序；写入次数有限。
- **SRAM**：掉电丢失，放变量/栈/堆。
- **GPIO**：通用输入输出，能读高低电平、输出高低电平。
- **定时器**：计数、PWM、定时中断、输入捕获。
- **ADC**：把模拟电压变成数字量。
- **DAC**：数字量变模拟电压（很多 MCU 没有）。
- **通信外设**：UART、I2C、SPI、CAN、USB 等。
- **看门狗**：程序跑飞时复位，提高可靠性。

## 4. GPIO

- 输出：点亮 LED、驱动蜂鸣器、给驱动器发信号。
- 输入：读按键、读传感器数字输出。
- 注意电平：3.3V 和 5V 不能随便互连；看 datasheet 的绝对最大额定值。
- 注意电流：GPIO 通常只能给几 mA 到几十 mA，不能直接驱动电机/继电器/大功率 LED。
- 上拉/下拉：给悬空输入一个确定电平。

```c
pinMode(LED_PIN, OUTPUT);
digitalWrite(LED_PIN, HIGH);

pinMode(BUTTON_PIN, INPUT_PULLUP);
bool pressed = digitalRead(BUTTON_PIN) == LOW;
```

## 5. ADC：把模拟量变成数字

- 分辨率：10 位 = 1024 级，12 位 = 4096 级。
- 参考电压：例如 3.3V；12 位时每级约 `3.3V / 4096 ≈ 0.8mV`。
- 采样率：每秒采样次数；太低会漏掉快速变化（混叠）。
- 输入范围：不能超过参考电压，否则可能损坏或读数饱和。
- 实际读数会抖动：加平均、RC 滤波、软件滤波；但要理解代价（延迟）。

```c
int raw = analogRead(SENSOR_PIN);          // 0..4095（ESP32 默认 12 位）
float voltage = raw * 3.3f / 4095.0f;
```

## 6. PWM：用开关控制平均功率

- 占空比：高电平时间 / 周期。
- 频率：周期倒数；LED 调光常用几百 Hz 到几 kHz，电机几 kHz 到几十 kHz。
- 平均电压 ≈ 占空比 × 电源电压（简化理解）。
- 用途：LED 调光、电机调速、加热控制、舵机信号（舵机不是普通 PWM 调速，见下）。

舵机：

- 常见 50Hz 周期（20ms），脉宽 0.5–2.5ms 对应角度。
- 不要用普通“占空比调速”的思路直接驱动舵机；要按舵机协议给脉宽。

## 7. 常见总线

| 总线 | 线 | 拓扑 | 速度 | 典型用途 |
| --- | --- | --- | --- | --- |
| UART | TX、RX、GND | 点对点 | 9600–几 Mbps | 串口调试、GPS、蓝牙模块 |
| I2C | SDA、SCL、GND | 多设备、地址 | 100k/400kHz | OLED、温湿度、EEPROM |
| SPI | MOSI、MISO、SCK、CS | 主从、多片选 | 几 MHz–几十 MHz | 屏幕、Flash、RFID |
| CAN | CAN_H、CAN_L | 总线、多节点 | 125k–1Mbps | 汽车、工业 |
| USB | D+/D- | 主机/设备 | 高速 | 下载、通信、供电 |

面试常问 I2C vs SPI：

> I2C 两根线、带地址、适合多个低速传感器；SPI 四根线、速度快、通常每个从设备一个片选，适合屏幕/Flash。I2C 有总线仲裁和上拉要求，SPI 更简单但线更多。

## 8. 中断、定时器、看门狗

- **轮询**：主循环不断查状态；简单，但浪费 CPU，响应不确定。
- **中断**：事件发生时打断 CPU；响应快，但 ISR 要短，不能做耗时操作。
- **定时器中断**：固定周期执行，适合采样、控制循环。
- **看门狗**：主循环定期“喂狗”；程序卡死时自动复位。
- **volatile**：中断和主循环共享的变量要加 `volatile`，防止编译器优化掉读取。

按键中断里不要 `delay`，只置标志位，主循环处理。

## 9. RTOS

裸机大循环（superloop）适合简单任务：

```c
while (1) {
    read_sensors();
    update_control();
    handle_comm();
}
```

RTOS 把任务拆开，由调度器切换：

- 任务（task）：独立执行流，有优先级。
- 调度：抢占式/时间片；高优先级先跑。
- 队列：任务间传数据。
- 信号量/互斥量：保护共享资源。
- 延时：`vTaskDelay` 让出 CPU。

什么时候需要 RTOS：

- 多个任务有不同周期/优先级。
- 需要阻塞等待（网络、存储、用户输入）。
- 任务间有明确的同步关系。

什么时候不需要：

- 一个循环能稳定跑完，时序简单。
- 用 RTOS 会增加内存、栈、优先级反转、死锁等复杂度。

## 10. 内存与常见坑

- Flash 放代码和常量；SRAM 放变量、栈、堆。
- MCU 上尽量少用 `malloc/free`；碎片和失败难查。
- 大数组/大缓冲要算清楚 SRAM 够不够。
- 栈溢出会表现成“随机死机”，很难查。
- `const`/`PROGMEM` 可以把常量放 Flash，节省 SRAM。
- 字符串、浮点运算在 8 位 MCU 上很贵；能整数就整数。

## 11. 编译、烧录、调试

```text
写代码 → 编译 → 链接 → 生成 hex/bin → 烧录 → 运行 → 看串口/示波器/调试器
```

- 编译错误：语法/类型/头文件。
- 链接错误：找不到函数/库、内存段溢出。
- 运行时错误：时钟、引脚、电源、初始化顺序、中断优先级。
- 调试手段：串口打印、LED 翻转、逻辑分析仪、示波器、SWD/JTAG 单步。

常见坑：

- 烧录成功但没反应：电源、地、启动模式、引脚复用。
- 串口乱码：波特率、时钟配置、电平。
- 一接电机就复位：电源掉压、地线太细、没有续流。
- 程序跑一会儿死：看门狗、栈溢出、内存泄漏、中断风暴。

## 12. 学哪块板子

| 板子 | 优点 | 适合 |
| --- | --- | --- |
| Arduino Uno | 生态最简单，资料多 | 零基础理解 GPIO/ADC/PWM |
| ESP32 | 便宜、Wi-Fi/BLE、双核 | IoT、无线、做完整项目 |
| STM32 | 工业常用、资料体系完整 | 打基础、求职、RTOS |
| 树莓派 | Linux、生态强 | 视觉/网络/上位机，不是实时控制首选 |

建议路线：

1. 先用 Arduino/ESP32 把 GPIO、ADC、PWM、串口玩熟。
2. 再上 STM32（HAL + 寄存器），理解时钟、中断、DMA、RTOS。
3. 不要一上来啃 STM32 寄存器；先让一个 LED 亮起来，再往下挖。

## 13. 面试一句话

- **MCU vs CPU**：MCU 把 CPU、Flash、RAM、外设集成在一颗芯片里，面向专用控制；CPU 通常指通用处理器，需要外部内存和外设。
- **GPIO**：通用输入输出，读/写高低电平；要注意电平、电流和上下拉。
- **ADC**：把模拟电压离散成数字量；分辨率、参考电压、采样率决定精度和速度。
- **PWM**：用占空比控制平均功率；LED 调光、电机调速、舵机信号都用它，但协议不同。
- **中断**：事件触发、打断主流程；ISR 要短，共享变量要 `volatile`。
- **I2C vs SPI**：I2C 两线带地址、适合多传感器；SPI 四线速度快、适合屏幕/Flash。
- **RTOS**：用任务和调度管理并发；简单系统用大循环更省事。
- **看门狗**：程序卡死时复位；要在主循环正常时喂狗，不能在中断里乱喂。

## 14. 小练习

1. 用 ESP32/Arduino 读一个电位器，串口打印电压；加 8 次平均，观察抖动。
2. 用 PWM 调 LED 亮度，从 0 到 100% 循环。
3. 用 I2C 点亮一个 OLED，显示“Hello”。
4. 用定时器中断每 100ms 采样一次，主循环做滤波。
5. 用两个任务（RTOS）分别闪 LED 和读串口，观察优先级的影响。

做到能解释“为什么这样接、为什么这样写”，比背 API 更有用。
